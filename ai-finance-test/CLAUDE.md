# 리스크 렌즈 — AI 추출 검증 테스트

## 이 레포가 하는 일

ETF 투자설명서(PDF)에서 LLM이 구조화된 필드를 추출할 수 있는지 검증하는 **테스트 코드**입니다. 서비스 구현 코드가 아닙니다.

답하려는 질문:
1. 투자설명서에서 필요한 항목이 실제로 추출되는가?
2. 추출값에 붙은 근거 원문이 실제로 문서에 존재하는가?
3. (별도 트랙) 투자설명서를 DART에서 자동으로 가져올 수 있는가?

상세 배경은 `docs/AI추출_테스트_실행계획_v1.md` 참조.

---

## 핵심 설계 원칙 (변경 시 사람에게 확인)

### 1. 트랙 A와 트랙 B는 분리한다

- **트랙 A** (이 레포의 주 작업): 입력은 **로컬 고정 PDF**. DART 조회를 절대 끼워 넣지 않는다.
- **트랙 B**: DART 수집 경로 검증. 별도 스크립트, 트랙 A 입력에 관여하지 않음.

이유: 값이 안 나왔을 때 "문서를 잘못 가져온 것"과 "AI가 못 읽은 것"을 구분해야 한다.

### 2. 종목명 파싱 보정은 채점 후처리다

종목명 파싱 보정(`(합성)`→복제방식 등)을 **추출 단계나 채점 전에 적용하지 않는다.**

- 채점은 **보정 전 원점수**가 기준
- 보정 후 점수는 `results_field.csv`의 **별도 컬럼**(`match_corrected`)에 기록

이유: 보정을 켜면 AI가 아무 값도 못 내놔도 24점 중 5점 안팎이 자동으로 채워져, "추출이 되는가"라는 원래 질문에 답할 수 없다.

### 3. 판단은 규칙, 읽기는 AI

| 단계 | 담당 |
|---|---|
| 종목명에서 구조 신호 추출 | 규칙 (문자열 매칭) |
| 문서에서 필드 추출 | AI |
| 위험 판정 | 규칙 |
| 이름 파싱 ↔ AI 추출 불일치 시 | 사람 (플래그만 남길 것) |

**불일치 시 AI 값을 자동으로 덮어쓰지 말 것.** `검증필요` 플래그를 남긴다. ETF 네이밍 규칙은 법적 강제가 아니라 업계 관행이므로 예외 가능성이 있다.

### 4. 근거 없으면 null

프롬프트에서 강제: 근거 원문을 찾지 못하면 값을 추측하지 말고 `null` 반환.
`null`은 오답과 별도로 집계한다. "틀린 값을 자신 있게 반환"보다 "모른다고 말하는 실패"가 서비스상 안전하다.

## 하지 않기로 한 것 (이미 검토 후 기각)

재제안하려면 아래 근거를 반박해야 함. 좋은 반박이면 바꿔도 됨.

| 항목 | 기각 사유 |
|---|---|
| **벡터DB (Pinecone, Chroma)** | 대상 ETF 4종 고정. 사용자가 종목을 지정하고 들어오므로 "무엇을 찾을지"가 이미 정해져 있음. 검색 문제가 아님 |
| **임베딩 기반 섹션 검색** | 목차/조항 번호가 정형화되어 키워드 매칭으로 충분. 자유형 Q&A 구현 시 재검토 |
| **PDF 텍스트 추출에 비전/LLM 사용** | 디지털 PDF면 라이브러리로 충분. AI가 문장을 미세 변형하면 근거원문 부분일치 검증이 깨짐. 스캔본으로 확인될 때만 검토 |
| **런타임 DART 실시간 조회** | 투자설명서는 정정 시에만 갱신. DART 장애가 서비스 장애가 되고, "10초 이내" 응답 약속 불가. 사전 배치 수집 → SQLite 캐시 구조 |
| **enum 값 관대한 채점** | enum은 규칙 엔진의 입력 키로 그대로 들어감. `"합성복제"`처럼 조금만 달라도 매칭 실패 |

## 실행 설계

### 조건
| 조건 | 입력 | 평균 input tokens |
|---|---|---|
| C1 | PDF 전문 텍스트 통째 (표는 수치 격자표 재구성해 덧붙임) | 73,393 |
| C2_wide | 요약정보+제1부1+제2부(1,6,7,8,9,10,13,14) | 38,269 |
| C2_narrow | C2_wide − 제2부10(투자위험 정형 고지문구) | 30,265 |

**C1 성립 확인 완료** (2026-08-22 실측, 최대 79,710 토큰). C2를 wide/narrow 두 갈래로 분리해 3조건으로 실행.

### 규모
```
3 조건 × 3 샘플(A/B/C) × 3 반복 = 27 회
seed = 42 고정  (temperature는 통제 불가 — 아래 참조)
```
반복 3회는 정확도가 아니라 **재현성** 측정용.

> ⚠️ **temperature=0 설계는 포기했다.** gpt-5 계열이 temperature 파라미터를 거부한다(2026-08-22 사람 확인).
> 재현성 측정이 `seed` 단독에 의존하므로, 반복 결과가 흔들려도 **"seed의 한계"인지
> "reasoning_effort로 인한 비결정성"인지 구분되지 않는다.** 재현성 수치 해석 시 반드시 감안할 것.

### 대상 샘플
| # | 종목명 | 종목코드 | 구조 |
|---|---|---|---|
| A | TIGER 미국S&P500레버리지(합성 H) | 225040 | 레버리지+합성+환헤지 |
| B | TIGER 배당커버드콜액티브 | 472150 | 커버드콜+액티브+월분배 |
| C | TIGER TDF2045 적격 | 0025N0 | 타겟데이트+자산배분 |

### 이번 라운드 범위
**Tier1 8슬롯만.** Tier2는 Tier1 통과(22/24) 후 확장.

`종목명` `지수` `레버리지배율` `복제방식` `환헤지여부` `전략유형` `분배정책` `총보수`

**`지수` 슬롯은 `기초지수` + `비교지수` 조합으로 1칸이다** (분모 24 = 8슬롯 × 3샘플).
액티브 ETF는 기초지수가 없어 정답이 `null`이며(B 투자설명서 p.27 제2부 9가 명시),
KRX 상장규정의 상관계수 기준(액티브 0.7 / 일반 0.9)이 이 구분의 법적 근거다.

## 채점 규칙

### 필드별 판정
| 필드 | 방식 |
|---|---|
| `종목명` | 공백·괄호 정규화 후 완전일치 |
| `기초지수` | `ground_truth.json`의 **허용 문자열 목록** 매칭 |
| `레버리지배율` | 수치 완전일치 (2.0 == 2) |
| `복제방식` `환헤지여부` `전략유형` `분배정책` | **enum 완전일치**, 표기 흔들림 불허 |
| `총보수` | 소수점 2자리 완전일치 |

### 근거 실재성 자동 검증
```
1) PDF 전문 텍스트를 공백·줄바꿈·특수문자 제거하여 정규화
2) AI 반환 근거원문도 동일 정규화
3) 부분일치(substring) 검사
4) 실패 시 앞뒤 10자씩 잘라 재시도 (앞뒤 잘림 대응)
5) 그래도 실패 → evidence_found = 0
```
`evidence_found = 0`이면 값이 맞았더라도 별도 표시.

### 통과 기준
- 정량: 22/24 이상 (**보정 전 원점수**)
- 근거 실재성: 정답 필드 중 90% 이상
- 재현성: 3회 반복 시 Tier1 불일치 0건
- 실패 방식: 오답 중 `null` 비율이 "확신 있는 오답"보다 높을 것

## 구현 시 주의

- **모델명은 `config.yaml`로 분리.** 하드코딩 금지 (추후 비교 가능성)
- OpenAI **Structured Outputs로 스키마 강제** — 검증 완료(JSON 파싱 실패 0/28). 프롬프트로 "JSON만 반환" 부탁하는 방식보다 안정적
- **`seed` 고정만으로는 결정적이지 않다.** temperature 통제가 불가능하므로 재현성은 실측으로만 확인
- **채점 스크립트는 Python 3.10+ 필요** (`int | None` 표기). 시스템 `python3`(3.9.6)로는 `TypeError`로 죽는다.
  반드시 `.venv/bin/python scripts/score_extraction.py`로 실행할 것
- 프롬프트에 "문서에 없는 내용을 사전지식으로 채우지 말 것" 명시 (예: "TIGER TDF2045는 보통…" 차단)
- **응답 시간 기록 필수** — 화면 카피 "보통 10초 이내로 완료됩니다" 검증용
- **페이지·조항 번호 추출 여부 기록 필수** — 근거 패널 UI("P. 42 / 제2부 9-나") 성립 여부 판단용
