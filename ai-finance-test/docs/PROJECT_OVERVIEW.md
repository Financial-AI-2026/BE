## 1. 이 레포가 하는 일

ETF 투자설명서(PDF)에서 LLM이 구조화된 필드를 추출할 수 있는지 검증하는 **테스트 코드**다. **서비스 구현 코드가 아니다.**

답하려는 질문:
1. 투자설명서에서 필요한 항목이 실제로 추출되는가?
2. 추출값에 붙은 근거 원문이 실제로 문서에 존재하는가?
3. (별도 트랙) 투자설명서를 DART에서 자동으로 가져올 수 있는가?

## 4. 실행 방법

> **반드시 `.venv/bin/python`을 쓸 것.** 스크립트가 Python 3.10+ 문법(`int | None`)을 쓰는데
> 시스템 `python3`은 3.9.6이라 `TypeError`로 죽는다.

```bash
# 1) PDF → 텍스트 (샘플 추가/PDF 교체 시에만)
.venv/bin/python scripts/extract_text.py

# 2) 표 복원 + 섹션 분할 (1번 이후 필수)
.venv/bin/python scripts/build_corpus.py

# 3) 추출 실행
.venv/bin/python scripts/run_extraction.py --full                       # 본 실행 27회
.venv/bin/python scripts/run_extraction.py --pilot                      # A × C1 × 1회
.venv/bin/python scripts/run_extraction.py --sample D --condition C2_wide --repeats 1 --prompt v2_tier1

# 4) 채점 (API 호출 없음. raw/*.json 재채점만)
.venv/bin/python scripts/score_extraction.py
```

`--prompt`는 `prompts/` 아래 파일명(확장자 제외). 기본값 `v1_tier1`.
API 키는 `.env`의 `OPENAI_API_KEY`에서 읽는다.

## 5. 이 프로젝트에서 반복해서 걸린 함정

**새로 들어온 에이전트는 이 절을 꼭 읽을 것.** 여러 번 같은 실수가 났다.

### ① 키워드가 없다고 사실이 없는 게 아니다

가장 자주, 사람·AI 가리지 않고 걸린 함정이다. 실제 사례:

- "D 문서에 `실물`이라는 단어가 무관한 맥락으로만 6회 → 복제방식 근거 없음"으로 판단했으나,
  실제 근거는 **투자전략 조항의 "장내파생상품에 투자" 문장**에 있었다.
- "`F-KOSPI 200`이 문서에 0회 → 지어낸 값"으로 판단했으나,
  **한글 표기 `F-코스피 200`으로 2회** 있었다. 영문 표기만 검색한 탓.

**교훈: 필드명 키워드로 grep해서 안 나오면 "없다"가 아니라 "다른 말로 적혀 있다"를 먼저 의심할 것.**

### ② 규제 표준조항은 판별력이 없다

투자설명서는 금융투자협회 표준 양식이라, 상품 성격과 무관하게 들어가는 보일러플레이트가 많다.

| 키워드 | A(합성) | B | C | D |
|---|---|---|---|---|
| 스왑 | 30 | 4 | 5 | 4 |
| 장외파생 | 69 | 20 | 21 | 19 |
| 거래상대방 | 79 | 19 | 18 | 16 |

"스왑·장외파생 언급이 없으면 실물"이라는 규칙은 **4개 문서 전부에서 발동하지 않는다.**
실물 상품 3종도 baseline으로 4~5 / 19~21 / 16~19를 갖기 때문이다.

또 `고난도금융투자상품 해당여부`는 **4개 문서 전부 "해당사항 없음"**이라 정답이 항상 false다.

**교훈: 규칙을 만들기 전에 4개 문서 전부에 대봐서 실제로 갈리는지 확인할 것.**

### ③ 같은 개념을 문서마다 다른 말로 쓴다

| | 리밸런싱 | 재조정 | 일간 | 일일 |
|---|---|---|---|---|
| A | 0 | 0 | 56 | 4 |
| B | 0 | 0 | 16 | 0 |
| C | **1** | 0 | 5 | 0 |
| D | 0 | **4** | 57 | 6 |

동일 개념에 A는 "일간", C는 "리밸런싱", D는 "재조정"을 쓴다.

**교훈: 판단 기준은 키워드가 아니라 "어느 조항을 읽어라"로 줄 것.**
v2가 복제방식을 고친 방식이 정확히 이거다 — `제2부 투자전략(운용전략 및 투자방침)` 조항을 지정했고,
이 조항은 모든 ETF 투자설명서가 규제상 반드시 갖는다.

### ④ LLM이 만든 정답지를 쓰지 말 것

외부 LLM에게 물어 만든 정답지를 문서와 대조한 결과, 8필드 중 **종목명이 규약 위반**(법정명이 아닌 거래용 시장명)이었고
근거로 제시된 지수명 표기도 문서와 달랐다. 정답지는 **문서 원문 + 공식 페이지 교차검증**으로 만든다
(총보수는 투자설명서 표 + 미래에셋 공식페이지 + FunETF 3중 교차검증으로 확정한 선례가 있다).

## 6. 핵심 원칙 (요약 — 정본은 CLAUDE.md)

1. **트랙 A와 트랙 B 분리** — 트랙 A 입력은 로컬 고정 PDF. DART 조회를 절대 끼워 넣지 않는다
2. **종목명 파싱 보정은 채점 후처리** — 추출·채점 전에 적용 금지
3. **판단은 규칙, 읽기는 AI** — 불일치 시 AI 값을 자동으로 덮어쓰지 말고 `검증필요` 플래그
4. **근거 없으면 null** — "틀린 값을 자신 있게"보다 "모른다고 말하는 실패"가 안전

CLAUDE.md의 "하지 않기로 한 것" 절(벡터DB, 임베딩 검색, 비전 OCR 등)은 **이 테스트 레포 범위 한정**이며,
"좋은 반박이면 바꿔도 됨"이 명시돼 있다. 실제 서비스 설계는 별개다
(예: 사용자가 넓은 ETF 풀에서 자유 질의하게 되면 벡터DB 재검토 대상).
