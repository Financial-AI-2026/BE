# Tier2 테스트 계획 v1

- 작성일: 2026-08-24
- 전제: Tier1 정량 기준 통과(C2_wide 평균 23.0, 3/3 PASS). [Tier1_테스트_결과보고서_v1.md](Tier1_테스트_결과보고서_v1.md) 참조
- 필드 원 정의: [개발자공유_AI추출_테스트명세서.md](개발자공유_AI추출_테스트명세서.md) 2절 "Tier 2 — 개인화 경고 생성에 필요"

---

## 1. 목적

Tier1은 "**상품이 무엇인가**"를 추출한다. Tier2는 "**이 사용자에게 왜 위험한가**"를 생성하는 데 필요한 재료를 추출한다.

예: `레버리지배율 2.0`(Tier1)만으로는 경고를 못 만든다. `일일리밸런싱여부 = true`(Tier2)가 있어야
"장기 보유 시 복리효과로 지수 2배와 다른 결과" 경고가 성립한다.

---

## 2. 대상 필드와 실측 기반 난이도 평가

명세서의 6개 필드에 대해 **A/B/C/D 문서를 실제로 조사한 결과**를 붙였다.
난이도는 추측이 아니라 실측이다.

| # | 필드 | 타입 | 잠정 정답 (A/B/C/D) | 난이도 | 근거 |
|---|---|---|---|---|---|
| 1 | `액티브여부` | bool | false / **true** / false / false | 🟢 쉬움 | "액티브" 등장 B 100회 vs 나머지 2회. 신호 명확 |
| 2 | `목표시점` | int\|null | null / null / **2045** / null | 🟢 쉬움 | C에 "2045" 102회. 나머지 0회 |
| 3 | `고난도금융투자상품여부` | bool | false / false / false / false | 🔴 **측정 불가** | 4/4 전부 "해당사항 없음" — 아래 참조 |
| 4 | `거래상대방위험` | bool | **true** / false / false / false | 🟡 주의 | 키워드 baseline 문제. 아래 참조 |
| 5 | `일일리밸런싱여부` | bool | **true** / false / false / **true** | 🟡 주의 | 문서마다 용어가 다름. 아래 참조 |
| 6 | `주요투자자산` | string[] | — | 🔴 어려움 | 배열 채점 규칙 미정. 아래 참조 |

> 정답값은 **잠정**이다. Tier2 실행 전에 `ground_truth.json`에 정식 등록하며 문서 원문으로 재확인해야 한다.
> LLM에게 물어 정답지를 만들지 말 것 — 그렇게 만든 정답지에서 규약 위반이 나온 전례가 있다.

### ③ `고난도금융투자상품여부` — 이번 샘플셋으로는 측정 불가

4개 문서 전부 동일하게 적혀 있다:

> "바. 고난도금융투자상품 해당여부 : **해당사항 없음**"

정답이 항상 `false`라, **AI가 아무 것도 안 읽고 `false`만 반환해도 4/4 만점**이 된다.
"추출이 되는가"를 측정할 수 없는 필드다.

**선택지 (사람 확인 필요):**
- (a) Tier2에서 제외하고, 고난도 상품에 해당하는 5번째 샘플 확보 시 재도입
- (b) 채점 분모에는 넣되 **판별력 없음**을 결과 보고서에 명시
- (c) 정답이 `true`인 샘플을 찾아 추가 (ELS·DLS 편입 상품 등)

문서 조항 자체는 정형화돼 있어(제1부 2-바) **추출 난이도는 낮다.** 문제는 측정 설계다.

### ④ `거래상대방위험` — 키워드로 판정하면 반드시 실패

| | A(합성) | B | C | D |
|---|---|---|---|---|
| "거래상대방" 등장 | 79 | 19 | 18 | 16 |

실물 상품 3종도 16~19회 나온다 — 담보관리·ISDA 표준 등 **규제 보일러플레이트**다.
"거래상대방 언급이 있으면 true"로 하면 4/4 전부 true가 된다.

**대응:** Tier1의 `복제방식`과 **완전히 같은 구조의 문제**이며, v2에서 이미 해결한 방식을 그대로 쓴다 —
`제2부 투자전략(운용전략 및 투자방침)` 조항 본문에서 이 펀드 자신이 장외파생 계약으로 지수 수익률을
수취하는지 판단하게 한다.

> 참고: `거래상대방위험`은 사실상 `복제방식 == 합성`과 동치다. **독립 필드로 둘 가치가 있는지 검토 필요.**
> 명세서는 "A에서 true + 상대방 증권사명"을 요구하는데, **증권사명이 실제로 문서에 있는지 미확인**이다.
> 있다면 그게 이 필드의 고유 가치이므로, ground_truth 작성 시 먼저 확인할 것.

### ⑤ `일일리밸런싱여부` — 문서마다 용어가 다름

| | 리밸런싱 | 재조정 | 일간 | 일일 |
|---|---|---|---|---|
| A | 0 | 0 | **56** | 4 |
| B | 0 | 0 | 16 | 0 |
| C | **1** | 0 | 5 | 0 |
| D | 0 | **4** | **57** | 6 |

같은 개념을 A는 "일간", C는 "리밸런싱", D는 "재조정"으로 쓴다. **키워드 규칙이 성립하지 않는다.**

또 `일간`은 B(비레버리지)에도 16회 나오므로 단순 등장 여부로도 안 된다.

**대응:** 프롬프트에서 조항을 지정한다. A의 실제 근거 문장 예시:
> "이 투자신탁은 '일간' 투자목적을 달성하기 위해 운용되는 펀드로, 단기거래를 위해 설계된 상품입니다."

D의 근거 문장 예시:
> "일일기준으로 포트폴리오 재조정이 이루어지기 때문에, 일간 보다 긴 기간동안의 투자신탁 수익률은 복리효과로…"

**둘 다 레버리지 상품의 투자위험 조항에 있다.** 이 조항을 근거로 삼도록 지정한다.

### ⑥ `주요투자자산` — 채점 규칙부터 정해야 함

Tier1은 전부 스칼라(string/float/enum/bool)라 **완전일치**로 채점했다.
`string[]`은 그 규칙이 적용되지 않는다. 결정 필요:

- **집합 완전일치**: `["글로벌 주식","국내외 채권"]`과 순서 무관 완전일치. 엄격하지만 표기 흔들림에 취약
- **허용목록 기반**: `기초지수`처럼 항목별 허용 문자열 목록을 두고 집합 비교. **권장**
- **부분 점수(F1)**: 겹치는 비율로 점수. Tier1의 "완전일치" 기조와 어긋남

Tier1이 `기초지수`에서 이미 허용목록 방식을 쓰고 있으므로 **일관성 측면에서 허용목록 권장**.

## 3. 설계 결정 사항 (실행 전 확정 필요)

### 3.1 스키마 개편을 같이 할 것인가

앞선 논의에서 나온 제안:
- `액티브여부`를 별도 필드로 추가 (현재 B의 액티브 여부는 `기초지수=null`로만 암묵 인코딩됨)
- `기초지수`/`비교지수`를 `지수` 1개로 병합

**Tier2에 `액티브여부`가 이미 포함돼 있으므로 자연스럽게 해소된다.**
다만 지수 병합은 별개 결정이며, A에서 기초지수(`S&P 500`)와 비교지수(`S&P 500 2X Leverage Daily`)가
**실제로 다르다**는 점을 감안해야 한다(레버리지배율로 파생 가능하므로 실질 손실은 작다는 판단은 가능).

> **권장: 지수 병합은 이번 라운드에 넣지 말 것.** Tier1 기초/비교지수가 현재 27/27 만점이라 고칠 이유가 없고,
> 스키마를 바꾸면 기존 baseline과 비교가 끊긴다.

### 3.2 Tier1과 같이 돌릴 것인가

**권장: 같이 돌린다(단일 호출로 Tier1 8슬롯 + Tier2 6필드).**

이유:
- 서비스 실제 형태가 단일 호출이다. 분리하면 응답 시간이 2배(현재 이미 중앙값 57초로 문제)
- Tier1 회귀 여부를 동시에 확인 가능
- 입력 코퍼스가 동일해 중복 토큰 비용이 없다

단, **출력 토큰이 늘어 지연이 더 길어질 수 있다.** 실측해서 기록할 것.

### 3.3 v2 프롬프트 검증이 먼저다

**Tier2를 v2 미검증 상태에서 시작하면 안 된다.** v2는 D에 1회 돌린 게 전부다.

Tier1 필드가 v2에서 회귀했는지 모르는 채로 필드를 6개 더 얹으면,
점수가 떨어졌을 때 "v2 탓인지 Tier2 추가 탓인지" 분리가 안 된다.
Tier1 라운드에서 변수를 하나씩 통제해 총보수 소수점 버그를 잡아낸 것과 같은 이유다.

## 4. 실행 계획

### 단계

| # | 단계 | 산출물 | API 호출 |
|---|---|---|---|
| 0 | **v2 본 검증** — A/B/C × C2_wide × 3반복 | Tier1 회귀·재현성 확인 | 9회 |
| 1 | Tier2 `ground_truth.json` 작성 (문서 원문 대조) | 정답지 + 근거 페이지 | 0 |
| 2 | 스키마 확장 (`schema_tier1.py` → Tier2 필드 추가) | 코드 | 0 |
| 3 | 프롬프트 v3 작성 (Tier1 v2 + Tier2 6필드) | `prompts/v3_tier12.md` | 0 |
| 4 | 파일럿 1회 (A × C2_wide) | 정답지 오류 조기 발견 | 1회 |
| 5 | 본 실행 — A/B/C/D × C2_wide × 3반복 | `runs.csv`, `raw/` | 12회 |
| 6 | 채점 + 판정 | 결과보고서 | 0 |

**총 22회.** Tier1 본 실행(27회)보다 적다 — 조건이 C2_wide로 확정됐기 때문.

> 4단계(파일럿)를 건너뛰지 말 것. Tier1 파일럿에서 **정답지 오류 4건**을 발견한 전례가 있다
> (A 분배정책이 명세서 원안 `무분배` → 실제 조항 확인 후 `연분배`로 정정).

### 샘플에 D를 포함하는 이유

Tier1에서 D는 held-out이었지만, Tier2에서는 **본 샘플로 편입**한다.
- Tier2 필드 중 `일일리밸런싱여부`는 레버리지 상품에서만 true인데, A(합성 레버리지)만으로는
  "레버리지=합성"이라는 가짜 상관을 다시 만들 수 있다. D(실물 레버리지)가 이를 깬다
- 분모가 4샘플 기준이 되어 6필드 × 4샘플 = **24**로 Tier1과 같아진다

단, D를 `config.yaml`의 `samples`에 넣으면 `--full`(27회) 정의가 바뀌므로
**Tier2 전용 실행 설정을 따로 두거나 `--sample`로 개별 지정**할 것.

## 5. 채점 기준 (초안)

| 필드 | 방식 |
|---|---|
| `액티브여부` `거래상대방위험` `일일리밸런싱여부` `고난도금융투자상품여부` | bool 완전일치 |
| `목표시점` | int 완전일치. 해당 없으면 `null`이 정답 |
| `주요투자자산` | 허용목록 기반 집합 비교 (3.6절 결정 따름) |

### 통과 기준 (초안 — 확정 필요)

- 정량: **20/24 이상** (Tier1의 22/24보다 완화)
  - 이유: Tier2는 "개인화 경고 생성"용 보조 필드이고, `주요투자자산`(배열)·`거래상대방위험`처럼
    난이도가 구조적으로 높은 필드가 포함된다. Tier1과 같은 기준을 적용할 근거가 없다
  - **단 `일일리밸런싱여부`는 예외로 A·D 모두 정확해야 한다** — 이게 틀리면 레버리지 장기보유 경고 자체가 생성 불가
- 근거 실재성: 90% (Tier1과 동일)
- 실패 방식: null > 확신 있는 오답 (Tier1과 동일)
- 재현성: temperature 통제 불가 이슈가 그대로 적용됨. Tier1 결과 보고 후 기준 재검토

## 6. 위험 요소

| 위험 | 내용 | 완화 |
|---|---|---|
| **정답지 오염** | LLM으로 정답지를 만들면 순환 검증이 됨 | 문서 원문 + 공식 페이지 교차검증. 파일럿으로 조기 검출 |
| **판별력 없는 필드** | `고난도` 4/4 동일값 | 3절에서 처리 방침 확정 |
| **키워드 함정 재발** | `거래상대방` `일일리밸런싱` 모두 baseline 존재 | 프롬프트에서 조항 지정 방식 사용 (v2 복제방식 선례) |
| **응답 시간 악화** | 출력 필드 6개 증가 | 실측 기록. 이미 "10초 이내" 카피는 성립 안 함 |
| **Tier1 회귀** | v3에서 Tier1 필드가 나빠질 수 있음 | 0단계(v2 본 검증)로 baseline 확보 후 비교 |

## 7. 사람 확인이 필요한 항목

- [ ] `고난도금융투자상품여부` 처리 방침 — 제외 / 포함하되 판별력 없음 명시 / 샘플 추가
- [ ] `거래상대방위험`을 독립 필드로 둘지 (`복제방식==합성`과 동치일 가능성). 증권사명 추출 가능 여부 먼저 확인
- [ ] `주요투자자산` 채점 방식 — 허용목록 집합 비교 권장
- [ ] Tier2 통과 기준 20/24가 적정한지
- [ ] 지수 병합(기초/비교 → 1필드)을 이번 라운드에 포함할지 — **권장: 미포함**
